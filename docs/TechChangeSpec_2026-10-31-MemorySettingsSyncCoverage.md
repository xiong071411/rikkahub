## 2026-10-31｜补齐记忆与用户偏好同步并校验发布包 (TechChangeSpec_2026-10-31-MemorySettingsSyncCoverage)

### 方案总览与实现要点

- 将助手独立记忆和 `__global__` 共享记忆作为 `memory_file` 实体纳入 Sync V2，支持初次补传、增量修改、删除、重试和双副本冲突处理。
- 将全部 Settings 顶层字段明确归类：37 个共享字段，15 个设备本地字段；新增序列化描述符完整性测试，新增字段未归类时测试失败。
- 新增 `app_preferences_v2` 扩展设置项承载此前遗漏的 14 个共享字段，避免 197 旧客户端写入旧版 `ai_preferences` 时覆盖新设置。
- 收齐分页后在一次 Settings 更新中应用助手、提供商及扩展设置，关联数据完整后再执行引用清理。
- 发布版本为 `3.1.4 / Build 198`，通过 CI 生成三种变体、四种架构组合的 12 个正式 APK，并使用实际 APK 内容验证门户分发。

### 问题回溯与根因分析

- 翻页按钮左右位置读取 `displaySetting.messageJumperOnLeft`，本地持久化正常，但增量引擎没有采集整个 `displaySetting`。
- 记忆开关位于 Assistant 配置中，记忆正文位于独立 Room 表 `memory_file`；原客户端未采集此表，服务端同步实体白名单和数据库也未支持它。
- 196 和 197 都保留手工设置白名单，既有协议场景测试未检查所有设置字段的同步归属，因此此前“全部内容已同步”的说法不成立。
- 首次拉取先写助手、后写 MCP、模式、世界书等依赖列表，每次写入均触发设置规整，可能提前清除尚未加载的关联 ID。
- 原推送成功后按 Outbox 行 ID 删除记录，网络请求期间新写入的记忆可能复用该行 ID；现改为按 mutation ID 确认，并保留新版本继续推送。
- 原发布门户曾只更新 Universal 包，单架构链接实际仍指向 196；本次将 12 包完整性、版本、签名、架构与代码一致性作为发布门槛。

### 受影响文件与关键点

- `data/sync/v2/MemorySyncPayload.kt`：记忆所有者、路径、正文与时间戳负载；实体 ID 为 UTF-8 `assistantId + NUL + path` 的 SHA-256，客户端与服务端一致。
- `data/db/dao/MemoryDAO.kt`、`data/repository/MemoryRepository.kt`：增加全量读取，本地写入和删除原子记录 Outbox；远端写入与本地编辑共用写锁，保护同步期间产生的新修改。
- `data/sync/v2/SyncSettingsContract.kt`：唯一共享设置范围定义、设备字段保留原因、兼容旧版的设置编码和批次应用。
- `data/sync/engine/IncrementalSyncEngine.kt`：采集和应用记忆，补拉旧客户端可能已跳过的新实体，批量应用设置；解析失败不再悄悄确认该设置已同步。
- `data/sync/v2/CanonicalSyncHash.kt`：记忆语义哈希忽略顶层 `updatedAt`，正文保持原文；头像和自定义字体进入客户端及服务端附件引用扫描，避免被当作孤儿文件回收。
- `di/DataSourceModule.kt`、`di/RepositoryModule.kt`：注入记忆仓库与同步记录器；`SyncTab.kt`：显示记忆冲突类型，纠正 Sync Token 提示。
- 服务端 `/root/rikkahub-web/backend/app/{models.py,database.py,memory_sync.py,canonical.py,services/sync_service.py,services/settings_service.py}`：增量建表 `memory_files`、能力声明、身份校验、记忆变更与墓碑、共享偏好聚合。
- `.github/workflows/build-arm32.yml`、`tools/verify_release_apks.py`、`tools/publish_portal_apks.py`：测试后构建全部包，缺失正式签名时失败，逐包校验后更新明确指定的门户目录。

### 行为变更明细

- 共享偏好新增：动态取色、主题选择、完整显示设置、快速模型推理级别、记忆模型及推理级别、生图模型、翻译模型及思考预算、OCR 模型、搜索公共配置及当前服务、当前 TTS 与 ASR 服务。
- 本机保留：加载状态、开发者开关、网络代理配置、当前助手选择、WebDAV/S3/临时上传存储凭据、内置 Web 服务配置和密码、备份提醒、本机同步配置与进度、赞助提示状态。
- 记忆正文同步与“同步图片与附件”开关无关；关闭附件同步仍能同步记忆。
- 旧版客户端继续使用原 Sync V2 实体和设置项；新版客户端要求服务端声明 `memory_file` 支持，避免误向未升级服务端推送。
- 新版首次运行重新核对一次云端基线，补拉旧版已跳过但推进过游标的实体；对 197 已确认但未落地的记忆废弃旧哈希，避免误跳过应用后生成删除操作；不清空本机内容或待推队列。
- 推荐升级顺序：先在仍保存完整记忆和偏好的原设备安装新版并同步，再在其他设备安装并同步。
- 门户使用带版本号和 Build 号的地址，旧版本归档保留，当前三种变体均提供 32 位、64 位、x86_64 与 Universal 下载。

### 性能与功耗评估

- 不增加后台轮询或 WakeLock；继续由用户发起同步并使用已有互斥锁串行执行。
- 记忆按文件分别记录修订、哈希和离线队列；内容未变不重复产生修订，仅在升级时补做一次基线核对。
- 设置批次收齐后一次更新、持久化与规整，减少逐条应用导致的重复对象重建和落盘。
- 自定义字体和头像继续通过已有附件队列与流式文件 I/O 传输；记忆正文不生成额外附件副本。
- 不改变 50% / 100% 比例、小屏圆屏布局或手表唤醒策略。
