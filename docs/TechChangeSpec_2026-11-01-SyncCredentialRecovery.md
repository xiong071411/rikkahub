# 同步凭据故障隔离（3.1.9 / 203）

用户反馈升级 202 后在同步第一阶段失败，界面仅显示“同步失败”。在线服务及能力接口正常，部分设备完成分页拉取后没有后续推送。现有备份包含绑定原设备 Keystore 的 SSH 密文；代码检查发现扫描工作区时任一凭据解密异常会中断整个同步，无消息的异常只留下通用失败提示。该缺陷可通过模拟异机恢复备份复现，但尚无用户真机异常栈，不能认定为唯一故障原因。

- 将不可解密的工作区单独标记为暂不可用，保留数据库中的完整原始记录，其他内容继续同步。
- 暂停这些工作区的新增、旧队列推送和删除，远端修改暂存到 Inbox；不上传空凭据、不改写既有基线，也不自动覆盖不可读的本地记录。
- 重新填写凭据后自动重试；初次对账遗留的本地与云端差异先保留至冲突中心。已有基线的记录继续使用原有冲突保护。
- 同步失败保留具体阶段及异常原因，无消息时显示异常类型；同步设置页持续显示错误和待处理工作区，取消操作仍正常传播。
- 本地工作区继续只同步配置，SSH 密码、私钥及私钥口令继续传输后在接收设备重新加密。

Android 测试和九包编译由 GitHub CI 执行，本机不运行 Gradle。本轮不修改后端及数据库结构。
