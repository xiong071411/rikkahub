## 2026-11-06｜聊天附件批量旋转 (TechChangeSpec_2026-11-06-BatchImageRotation)

### 方案总览与实现要点

关闭“跳过图片编辑”后，多选图片进入独立的批量旋转界面。默认全选，支持旋转 180°、左转 90°、右转 90°、重置、全选/取消全选与使用原图。确认前只改变缩略图的预览角度，确认后才在后台依次生成聊天附件。

### 问题回溯与根因分析

原有 `ChatAttachmentPicker` 只有在 `!skipCropImage && selectedUris.size == 1` 时调用单图编辑器，多张图片直接复制为附件，因此该设置无法用于多图方向修正。

### 受影响文件与关键点

- `ChatAttachmentPicker.kt`：分别处理跳过编辑、单图裁剪和多图旋转三个入口。
- `BatchImageRotationDialog.kt`、`BatchImageRotationState.kt`：管理每张图片的选中状态和累计旋转角度，显示缩略图预览与批次进度。
- `BatchImageRotationLauncher.kt`、`BatchImageRotationProcessor.kt`：逐张准备附件，全部成功后一次性加入输入框；失败或取消清理已生成附件与临时文件。
- `ImageCropImage.kt`、`ImageRotation.kt`：复用 EXIF 方向校正与尺寸限制，对完整图片进行实际像素旋转。
- 三组 `BatchImageRotation*Test`：验证混合选择、角度抵消、顺序、失败清理、取消清理和真实位图旋转。
- `.github/workflows/build-arm32.yml`：执行新增测试及现有裁剪回归，构建三种变体的九个 ARM 正式安装包。
- `tools/verify_release_apks.py`：同时核查批量旋转功能代码标记，防止发布旧包。

### 行为变更明细

- 单图继续使用现有裁剪编辑器；开启“跳过图片编辑”时继续直接导入。
- 多图默认全选；取消勾选只排除下一次旋转操作，不会删除该附件或撤销其已有角度。
- 左转、右转和 180° 操作可叠加；累计一周自动归零，归零图片直接复制原文件。
- “重置”清除所有图片的角度，包括已取消勾选的图片；“使用原图”直接导入这一批原始图片。
- 保持选择顺序，只在整批成功后添加到输入框，原相册文件始终保持原样。
- 确认后的处理期间禁止重复确认和关闭；处理失败显示具体图片序号，保留编辑状态以便重试或选择原图。
- 旋转导出与现有单图编辑一致，长边最多 4096 像素；照片保存为 JPEG（质量 90），带透明通道的图片保存为 PNG。未旋转图片不解码或重新编码，动图旋转后导出静态图片。

### 验收用例与标准

1. 关闭“跳过图片编辑”，选择单图仍打开原编辑器，多图打开批量旋转界面；开启该设置后直接导入。
2. 多选倒置图片，一次点击 180° 后完成，输入框附件及实际发送的图片方向正确。
3. 混合选择、取消全选、重新全选不改变附件数量或顺序，旋转只影响勾选图片。
4. 左右各转一次、旋转 180° 两次或旋转 90° 四次恢复原图；重置覆盖所有已编辑图片。
5. 分别验证奇数/偶数次 90° 的真实像素排列、EXIF 为 180° 的照片、透明 PNG 和大图尺寸限制；覆盖 Android 27 与 35 的两种解码路径。
6. 中途图片读取失败、页面销毁导致取消时，不向输入框添加部分结果，已准备的附件被清理。
7. CI 通过相关 JVM 回归与完整正式构建后，逐包验证版本、包名、签名、架构、功能标记及同变体 DEX 一致性。
8. 手机、方屏与圆屏真机可按上述路径检查预览、操作区滚动、确认按钮与附件发送结果。

### 性能与功耗评估

缩略图使用现有 Coil 按显示尺寸加载；预览只记录角度并改变绘制变换，不反复解码或编码大图。确认后按顺序解码、旋转、保存并立即回收单张位图，避免同时持有整批大图。文件复制、解码和编码位于 IO 线程；界面每完成一张图片更新一次进度，无后台轮询和新增 WakeLock。

操作区随网格滚动，给矮屏幕保留预览空间；圆屏额外预留四周安全边界，方屏和手机使用常规系统栏边距。实体设备显示与实际发送仍需真机验收，CI 的位图测试验证处理文件的像素与方向。

### 风险与回滚策略

旋转后的静态图片会重新编码，大于尺寸上限的图片会缩小，与现有单图编辑一致；需要保留源文件时可选择“使用原图”。发布前备份门户首页与被替换的下载别名，保留原版本安装包及混淆映射。故障时恢复门户备份并指向上一版 Build 204。

### 版本信息与变更摘要

版本由 `3.1.10 / Build 204` 升级为 `3.1.11 / Build 205`。基于已发布 Build 204 的提交 `17fbf57c` 开发，构建、Gradle 单元测试均交由 GitHub CI；本机仅执行代码检查和产物验证。发布目标为本机 `rikkahub-portal.service` 实际配置的下载门户，三种变体各提供 ARM 32 位、ARM 64 位与 Universal 包，保留其他项目及历史下载区域。
